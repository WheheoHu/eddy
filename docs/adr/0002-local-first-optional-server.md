# 0002 本地优先，服务端可选

状态：已采纳

## 决定

- 默认是单机模式：客户端通过 `eddy-source-greader` 直接连 FreshRSS，所有数据存在本机。
- 服务端模式：设置里填上服务端地址后，客户端通过 `eddy-server` 同步，由服务端接手 FreshRSS 对接。
- 两种模式都实现 `eddy_core::Upstream`：`DirectUpstream` 和 `HubUpstream`。界面层和其他 crate 不关心当前模式。
- 抓取、全文提取、付费墙抓取策略、AI 都在客户端执行。服务端只负责 FreshRSS 对接、同步、全量搜索和私有配置下发，不主动抓网页。

## 为了能无缝迁移而定下的约定

- 条目 ID 确定性生成：订阅文章 = UUIDv5(来源账号 ID, 上游文章 ID)；来源账号 ID = UUIDv5(规范化后的服务地址, 用户名)。保存的网页和系列用 UUIDv7。
- 所有本地修改先写操作日志，每条带混合逻辑时钟（HLC）。第一次连接服务端时，把本地日志整体上传，服务端按字段"后写入覆盖先写入"合并。
- 同步协议：客户端上传操作日志，按服务端递增序号拉取变更，应用打开时用 WebSocket 接收推送。不引入 CRDT。

## 单机模式下没有的功能

跨设备同步、全量历史搜索（只搜本机数据）、私有规则包和 AI 设置的自动下发（改成本机导入和配置）。

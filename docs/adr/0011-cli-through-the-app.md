# 0011 命令行经过应用操作用户的数据，数据目录只有一个主人

状态：已采纳

## 决定

- `eddy-cli` 从开发调试工具变成给人和 Agent 用的命令行（终端里叫 `eddy`）：添加内容、管理订阅、查询条目和正文、读写阅读进度。每条命令默认输出给人看的文字，加 `--json` 输出一个 JSON 对象。
- **用户真实的数据目录只由应用打开。** 命令行对它的一切操作都经过运行中的应用：应用启动后在数据目录里开一个 Unix 套接字（`control.sock`，权限 0600，并校验对端是同一个用户），命令行把请求发过去，应用用自己的引擎执行。应用没在运行时，命令行在后台把它启动起来（`open -g -j … --args --background`，不抢焦点）再发请求。
- 命令行有两种模式，由它在哪里决定，而不是由用户记得加什么参数：
  - **应用模式**：可执行文件在 `X.app/Contents/Helpers/` 里时的默认模式，操作用户的数据。
  - **独立模式**：`--data DIR`，引擎在命令行自己的进程里打开那个目录，密钥放在目录里的文件中。仓库里构建出来的副本（`target/` 下）默认就是这个模式，目录是 `build/cli-data`；它只有在显式加 `--app` **并且**设置了 `EDDY_DATA_DIR`（指向一个测试用应用的数据目录）时才走应用模式，所以开发时不可能碰到用户的数据。`--data` 指向应用默认数据目录时拒绝执行。
- 每条命令只实现一次：新的 `eddy-control` crate 里的 `execute(&Engine, Request)`。独立模式直接调用它，应用模式由应用里的套接字服务调用它。结果是 `eddy-control::dto` 里专门的类型，和引擎内部类型分开（`Item` 的序列化形式属于同步协议，不该同时充当对外的接口）；每个结果都是对象，只增加字段。
- 改了数据的请求执行完后，服务端调用引擎的变更通知，界面按已有的路径（同步变更时走的那条）重新读取列表。
- 协议是一行一个 JSON：一个请求，若干进度行，最后一行结果或错误。错误带稳定的英文代号（`not_found`、`offline`、`invalid`、`app_unreachable`…），文字仍是引擎现有的中文。请求里带协议版本 `CONTROL_VERSION`，不一致时提示重启应用（命令行和应用来自同一个应用包，不一致只会发生在应用更新后还没重启的时候）。
- 账号、配对、登出并清除这些命令只在独立模式下有：用户自己数据的账号在应用的设置里管理。
- 进 PATH 由用户在设置里点按钮完成：在 `/usr/local/bin/eddy` 建一个指向应用包内二进制的符号链接。应用不在启动时自己安装任何东西。

## 理由

- 两个进程同时打开一个数据目录在今天的引擎里是坏的：tantivy 的写锁只有一个，后打开的进程搜索静默失效、写入的内容进不了索引；`Engine::open` 会把另一个进程正在跑的视频任务标成失败；两个进程用同一个设备 ID 当混合逻辑时钟的节点，同一毫秒的两次修改可能得到相同的时间戳。让引擎变得多进程安全要动的地方很多，而"只有一个主人"一条规则就把这些都排除了。
- 应用看不到别的进程写进数据库的改动（它不监听数据库），只有经过它自己的引擎，界面才会跟着变。
- 密钥在应用的钥匙串条目里，按代码签名授权。命令行自己去读会弹授权框，应用每次写密钥又会把授权重置。经过应用就不需要共享密钥，命令行也拿不到任何密钥：协议里没有返回密钥的请求。
- 经过应用还让保存网页用上应用的 WebView 渲染，和在应用里保存的结果一样。
- 套接字放在数据目录里而不是固定位置，所以用 `EDDY_DATA_DIR` 启动的测试应用和用户自己的应用互不干扰。路径太长放不进套接字地址（macOS 是 104 字节）时，套接字改放到 `/tmp/eddy-<uid>/`，数据目录里的 `control.path` 记下它在哪。

## 后果

- 没有图形会话的远程登录里用不了应用模式；应用被命令行启动后会留在后台运行（Dock 里有图标）。
- 应用里的请求各在自己的线程上执行：应用里 tokio 运行时只有一个线程（UniFFI 的 `async-compat`），直接在上面读数据库或转换网页会卡住应用的网络请求。
- 命令行让应用代为读写文件（导入、导出）时先经过 `/tmp/eddy-<uid>/` 中转：应用不去读用户的"下载"之类的目录，否则系统的授权框会弹在一个隐藏的应用上。
- 引擎在数据目录里新增了 `control.sock` 和 `control.path`，已加入登出清除的列表。
- Windows 上没有应用，命令行只有独立模式。
- 同一个用户的任何进程都能通过套接字操作数据，这和它们本来就能直接读写数据库文件是一样的权限。

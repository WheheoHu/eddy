# 0003 文档结构、定位器和两条渲染路径

状态：已采纳

## 文档结构

网页文章、订阅正文、保存和捕获的页面，一律由 `eddy-doc` 转成扁平的块列表（标题、段落、列表项、引用、代码、公式、图片、表格、媒体、分隔线），块内是带样式的文本片段。原站 CSS 和版式不保留。

- 每个块有稳定 ID：由块类型和规范化文本求哈希，同一文档里重复的内容加序号。改动一个块不影响其他块的 ID。
- 公式统一存成 LaTeX：识别 MathML、KaTeX 附带的 TeX 源码、MathJax 的 `math/tex` 脚本。
- 文档结构带 `SCHEMA_VERSION`。每个内容版本都保存原始内容，结构升级或提取规则改进时重新生成，不用重新抓取。
- 文本偏移一律是 UTF-16 码元。

## 定位器

阅读进度、标注、跨设备跳转都用 `eddy_model::Locator`：内容版本哈希、具体位置（文章：块 ID 加块内偏移；EPUB：章节文件加章内进度，可选 CFI；PDF：页码加页内进度）、一小段原文上下文（选中文字和前后文），再加总进度。内容版本变化时，先按块 ID 找，找不到就用原文上下文模糊匹配。

## 渲染路径

- 文章阅读器（重排）：Apple 端是 TextKit 2，每篇文章一个文本视图，图片、代码、表格、公式、视频是内嵌附件。结构表达不了的内容用原网页 WebView 兜底。
- 出版物阅读器（保真）：PDF 用 PDFKit，进度按页记录（`Position::Pdf`），文字视图的位置不覆盖页码。EPUB 原版式的 WebView 以后再做，现在走重排。
- 渲染器在平台层登记，内核只给出内容类型和可用视图。

## 导入的文件

- 原文件整个存成固定（pinned）的 blob，作为每个内容版本的原始内容，结构升级时从它重新生成；服务端模式下随内容版本上传。
- EPUB 导入成系列：按目录把阅读顺序里的文件分组成章，一章一个条目（`ItemKind::Chapter`），章节 XHTML 转成块结构，用文章阅读器重排。书里的图片和链接用 `epub://<blob key>/<包内路径>` 寻址，按需从书里读取。
- PDF 导入成保存的条目，内容格式是 PDF。文字由内核用静态链接的 pdfium 读取（`eddy-pdf`，通过 `PdfReader` 接入，各平台共用），连同每行的位置和字号交给 `pdf_layout` 重排：去掉重复的页眉页脚和页码，按栏间空白分栏，按字号和加粗识别标题，再合并成段。结果用于搜索、摘要、翻译和文字视图；服务端没有读取器，照样能打开，只是没有文字。
- PDF 里的配图按阅读顺序插成图片块，"Figure N" 一行作图注。位图对象直接解码（能直接显示的 JPEG 原样输出）；嵌入的图形（form XObject，pdflatex 插入的 PDF 图就是这种）按它实际绘制的区域从页面渲染。封面、整页背景、压在正文下的底图、多页重复的 logo 和水印、页边和过小的装饰都不提取。图片地址是 `pdf://<PDF blob>/<页>/<对象序号>`，只有 base 也是同一 PDF 的文档能引用；像素在显示时由读取器按需解出，和 EPUB 里的图片一样缓存成可淘汰的 blob，随时能从原 PDF 重新生成。
- 导入的书、PDF 和保存的网页在界面上统一成 Collection，删除也按 Collection 的项进行，见 [0006](0006-collection-and-deletion.md)。

# 0008 视频演讲转多章图书与双端后台任务队列

状态：已采纳

## 决定

- 视频演讲与技术发布会（在线视频链接或本机视频文件）可由 `eddy-video` 转换成深度重排的多章图文书：提取原生字幕或经语音识别（ASR）得到时间轴讲稿，定位关键幻灯片与演示时刻并截取高清画面，再按逻辑章节交由写作模型去口语化深写，连同导读、配图、代码块、公式与表格打包成标准多章 EPUB 3，经 `import_epub` 一次性原子入库到 Collection 的 `Books` 分类。
- 生成过程（通常 5 至 15 分钟）走纯后台任务队列（本地表 `video_jobs` 与阶段检查点目录 `video-jobs/<id>/`），不在操作日志里写入半成品章节；中断或单章失败时从已落盘的转写稿、视觉大纲和已完成章节断点续跑，成功后自动清理临时音视频文件。
- 内置两条两阶段管线，统一由 `ASR`、`Stage 1`（视觉规划与选帧）、`Stage 2`（分章深度写作）三组独立端点配置驱动，每组端点同时支持 OpenAI 兼容协议（`/v1`）与 Gemini 原生协议（`/v1beta`）：
  1. 主力管线（`GeminiTwoStage`）：Stage 1 由 Gemini 原生视频接口扫描视频流（YouTube 直传 `fileUri`，本地或非 YouTube 视频自动按约 25 分钟切分为轻量内联代理流）定位完整态幻灯片时间戳，回原视频按清晰度比选截取 `1080p` 画面并做感知哈希去重；Stage 2 按章节并发成文。
  2. 兜底管线（`LocalFramesTwoStage`）：不具备原生视频端点时，由本地 `ffmpeg` 低阈值场景检测、尾帧清晰度优选与 `dHash` 拼图交给常规多模态模型完成 Stage 1 选帧与章节规划，再进入 Stage 2。
- 双端协同与密钥隔离（对 [0002](0002-local-first-optional-server.md) 和 [0005](0005-client-side-ai.md) 的受控扩展）：
  - 单机模式与本地视频文件一律在客户端执行（利用本机硬件加速解码，避免上传数 GB 原片），成书后随常规内容版本同步。
  - 已连接 `eddy-server` 且服务端就绪（容器内置 `ffmpeg` / `yt-dlp` 并配置了环境变量密钥，`ServerInfo::video_capable == true`）时，在线视频链接可投递给服务端 `/v1/video-jobs` 后台执行，客户端合盖离线也不中断；成书后写入服务端操作日志并通过 WebSocket 推送到所有已配对设备。
  - 客户端各阶段 API Key 只存本机钥匙串，绝不上传；服务端只从自身环境变量（`deploy/.env`）读取 `EDDY_VIDEO_*` 密钥，仅向客户端公开布尔就绪状态。

## 理由

- 复用标准多章 EPUB 3 作为最终原子入库载体，使新功能无需改动 [0003](0003-document-model-and-locator.md) 的文档块模型、[0006](0006-collection-and-deletion.md) 的系列删除回收逻辑以及 `eddy-sync` 的单 blob 同步协议（一本含 70 余张 `1080p` 配图的长篇讲义约 8 MB，远低于 256 MB 同步上限），左侧分章目录、跨章阅读进度和全文搜索开箱即用。
- 两阶段职责分离消除了单次长上下文生成的后半程缩水问题；把任务队列与检查点留在设备/服务端本地表，避免未完成状态污染多端同步日志。
